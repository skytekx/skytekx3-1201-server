- Hosting: The first bundling of the jar put it into git as `local-mods/ZeroCore2-1.20.1-2.1.48.jar`, because tools/build_mrpack.py read `local-mods/` from git HEAD only. Pushed to the public GitHub repository skytekx/skytekx3-1201-server, github.com would have served it as a download of its own, which the repost clause does not cover, so the Status said VERIFY. On 2026-11-05 the owner was offered three ways out: keep the jar out of git and fetch it at build time (A, the recommended default), go back to the Modrinth builds Extreme Reactors 2.0.84 and ZeroCore 2.1.45 (B), or ask the author to allow the copy in the repository (C). The owner answered "continue", so A was taken on 2026-11-06, and B and C stay possible later (okf/open-items.md, owner decisions). Git tracks only the pointer `local-mods/ZeroCore2-1.20.1-2.1.48.jar.fetch.json`, which names https://mediafilez.forgecdn.net/files/7344/725/ZeroCore2-1.20.1-2.1.48.jar with the size and SHA-1 above, and `.gitignore` ignores the jar path. tools/build_mrpack.py downloads the file into its cache, refuses the build unless size and SHA-1 match and ships the jar in `overrides/mods/` as before. tools/fetch_local_mods.py fetches it with the same checks for operators who mirror `local-mods/` into `mods/`. On 2026-11-06 that URL served 1,341,342 bytes with this SHA-1, the size and SHA-1 that the CurseForge API reports. No pushed commit ever held the jar. It came into git after 5947d4e, the tip of origin/claude/twilight-forest-port-mods-j2owbq, and on 2026-11-06 `git log --find-object` with its blob id f94d426ce1c02a3d3cbb16ddaf09db424c5435ae found it in none of the remote-tracking branches. The unpushed commits that tracked it are rewritten without it before any push, and tools/build_mrpack.py and tools/publish_modrinth.py refuse while any commit reachable from HEAD holds that blob.
- Distribution flag: The CurseForge allowModDistribution flag could not be read from CurseForge itself on 2026-11-04 and 2026-11-05: the CurseForge API needs a key, and the site API and api.curse.tools answered 403 or a Cloudflare challenge. The public API proxy cfproxy.bmpm.workers.dev reports allowModDistribution true for ZeroCore 2 and Extreme Reactors on 2026-11-05, but it reports true for Cupboard, Connectivity and Hexxit Additions as well, whose flag other records here call off, and the Curse Maven test answers 200 for this file just as for Cupboard and Hexxit Additions, so neither settles the flag. The grant in the description is the permission this record rests on, as for Fast Leaf Decay and Enchanting Plus. A modified ZeroCore would need the author's permission. This jar is unmodified.
